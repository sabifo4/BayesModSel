# TEST CASE 2: a Bayesian model selection analysis on the origin of animals

## Diversification models for the origin of animals evaluated under a Bayesian model selection analysis

Our second test case consisted of assessing how well two diversification models on the origin of animals fit the 54-animal dataset (sequence alignment and calibrated tree topology) assembled by  [dos Reis et al. (2015))](https://doi.org/10.1016/j.cub.2015.09.066):

* **_Unconstrained_**: this diversification model sets the maximum age of the calibration density used to constrain the age of node Metazoa  based on the Bitter springs preserved biota at ca. 833 Ma [Benton et al. (2011)](https://palaeo-electronica.org/content/pdfs/424.pdf). This interpretation of the fossil record was followed by [dos Reis et al. (2015)](https://doi.org/10.1016/j.cub.2015.09.066); their inferred evolutionary timeline placed the age of node Metazoa within the Cryogenian period. Based on this model, we now derive a stricter model in which the calibration density used to constrain the age of node Metazoa has a hard maximum bound. Please note that we have used the tag `dReta15pUhb` (i.e., initials of the first author in the study followed by the year it was published and then by the tail **p**ercentage of the **U**pper bound in the calibration density has a **h**ard **b**ound) to rename files/directories and identify the analyses carried out under the assumptions of this diversification model. The calibrated tree file [`54sp_s1_dRetal15pUhb.tree`](00_data_formatting/trees/dRetal15pUhb/54sp_s1_dRetal15pUhb.tree) is the same file that was used by [dos Reis et al. (2015)](https://doi.org/10.1016/j.cub.2015.09.066) when they were testing their calibration strategy 1 (i.e., original file name: `strategy1.tree`; this file and others can be downloaded from their Supplementary Material [available on FigShare](https://figshare.com/articles/dataset/Uncertainty_in_the_timing_of_origin_of_animals_and_the_limits_of_precision_in_molecular_timescales/1525089?file=2230069)) except from the tail probability set to "1e-300" instead of "0.001" to enforce a hard maximum on node Metazoa. We tested this model under both **GBM** and **ILN** relaxed-clock models.
* **_Late Ediacaran_**: based on a literal interpretation of the fossil record, [Budd and Mann (2024)](https://doi.org/10.1093/sysbio/syad057) suggest that the age of node Metazoa **cannot** be older than 580 Ma based on the oldest Ediacaran assemblages ([Μatthews et al. 2021](https://doi.org/10.1130/B35646.1)) that set the boundary between the Late Ediacaran and the Cambrian period, which disagrees with the animal evolutionary timeline inferred by [dos Reis et al. (2015)](https://doi.org/10.1016/j.cub.2015.09.066). Based on this model, we derived a stricter one in which the calibration density used to constrain the age of node Metazoa has a hard maximum bound. We may therefore use either `BM23` or `BM24` when referring to the study of [Budd and Mann (2024)](https://doi.org/10.1093/sysbio/syad057), but both refer to the same study. Please note that we have used the tag `BM23pUhb` (i.e., initials of the authors in the study followed by the year it was published online [2023] and then by the initials of the type of constraint place on the age of node Placentalia: tail **p**ercentage of the **U**pper bound in the calibration density has a **h**ard **b**ound) to rename files/directories and identify the analyses carried out under the assumptions of this diversification model. The calibrated tree file [`54sp_s1_BM23pUhb.tree`](00_data_formatting/trees/BM23pUhb/54sp_s1_BM23pUhb.tree) we have used in this study includes all the node age constraints under hypothesis "Late Ediacaran" in `MCMCtree` notation; this is the same file that was used by [Budd and Mann (2023)](https://doi.org/10.1093/sysbio/syad057) but includes the tail probability "1e-300" instead of "0.001" to enforce a hard maximum on node Placentalia. We tested this model under both **GBM** and **ILN** relaxed-clock models.

> <i>NOTE: Please note that dRetal15 tested 4 different calibration strategies, but we carried out our Bayesian model selection analyses when assuming <b>strategy 1</b>: all calibration densities were modelled as uniform distributions with soft bounds, having tail percentages of 0.001 on both sides except from the hard maximum bound used to constrain node Metazoa.</i>

As aforementioned, please remember that we have used the following tags to rename files/directories and identify the analyses carried out under the assumptions of a specific diversification model:

* `dRetal15pUhb`: tag used to rename files/directories and identify analyses where a stricter version of the diversification model used by [dos Reis et al. (2015)](https://doi.org/10.1016/j.cub.2015.09.066) has been integrated.
* `BM23pUhb`: tag used to rename files/directories and identify analyses where a stricter version of the diversification model postulated by [Budd and Mann (2023)](https://doi.org/10.1093/sysbio/syad05) has been integrated.

## Navigating this GitHub repository for data reproducibility

In order to easily navigate through our analyses and reproduce our results, please follow the links in the file structure below:

* [`00_data_formatting`](00_data_formatting/README.md): in this directory, you will find a description of the input files (sequence alignment and tree files) we have used to run our Bayesian model selection analyses.
  * [`aln`](00_data_formatting/aln): the [`dummy.txt`](00_data_formatting/aln/dummy/dummy.txt) file (generated using the `R` script [Generate_dummy_aln.R](00_data_formatting/aln/dummy/Generate_dummy_aln.R)) can be found in this directory. As the [`in.BV`] file was not available for both alignment blocks (i.e., a two-partition alignment was used by dRetal15), we have included the first alignment block ([aln_part1.phy](00_data_formatting/aln/aln_part1.phy)) and the second alignment block ([aln_part2.phy](00_data_formatting/aln/aln_part2.phy)) separately so that we can calculate the branch lengths, the gradient, and the Hessian using `CODEML` (more details about these analyses in the [`README.md` file under `01_modsel_workflow` section](01_modsel_workflow/README.md#1-hessian-and-gradient-inference-with-codeml)). The original two-partition alignment file has also been included ([aln-2P.phy](00_data_formatting/aln/aln-2P.phy); also available to download from their Supplementary Material [on FigShare](https://figshare.com/articles/dataset/Uncertainty_in_the_timing_of_origin_of_animals_and_the_limits_of_precision_in_molecular_timescales/1525089?file=2230069)), which we used when running `MCMCtree` for the subsequent analyses.
  * [`trees`](00_data_formatting/trees)
    * [`BM23pUhb`](00_data_formatting/trees/BM23pUhb): the [`54sp_s1_BM23pUhb.tree` file](00_data_formatting/trees/BM23pUhb/54sp_s1_BM23pUhb.tree) includes the node age constraints following [Budd and Mann (2024)](https://doi.org/10.1093/sysbio/syad057) except for the maximum age constraint on node Metazoa: a strict hard bound is used instead.
    * [dRetal15pUhb](00_data_formatting/trees/dRetal15pUhb): the [`54sp_s1_dRetal15pUhb.tree` file](00_data_formatting/trees/dRetal15pUhb/54sp_s1_dRetal15pUhb.tree) includes the node age constraints following [dos Reis et al. (2015)](https://doi.org/10.1016/j.cub.2015.09.066) except for the maximum age constraint on node Metazoa: a strict hard bound is used instead.
    * [Uncalibrated tree](00_data_formatting/trees/uncalib): the [`uncalib_animal.tree` file](00_data_formatting/trees/uncalib/uncalib_animal.tree) has the same tree topology as the other calibrated topologies but without labels (i.e., no node age constraints in `MCMCtree` notation); this is the format required by `CODEML`, which will be used to generate the `in.BV` with estimated branch lengths, gradient, and Hessian that will be later used by `MCMCtree` to approximate the likelihood calculation ([dos Reis and Yang 2011](https://academic.oup.com/mbe/article/28/7/2161/1051613)).
* [`01_modsel_workflow`](01_modsel_workflow/README.md): in this directory, you will see one directory for each step that needs to be run named after the main program used to do so.
  * [`00_CODEML`](01_modsel_workflow/00_CODEML/): the first step was to obtain the `in.BV` file for subsequent analyses with `MCMCtree` so that the likelihood calculation can be approximated ([dos Reis and Yang 2011](https://academic.oup.com/mbe/article/28/7/2161/1051613)). For all the details regarding this analysis, please read the first section in the [`README.md` file inside the `01_modsel_workflow` directory](01_modsel_workflow/README.md#1-hessian-and-gradient-inference-with-codeml).
  * [`01_mcmc3r`](01_modsel_workflow/01_mcmc3r/): we used the `mcmc3r` `R` package ([dos Reis et al. (2018)](https://doi.org/10.1093/sysbio/syy001)) to prepare the file structure and control files that will be subsequently used by `MCMCtree`.
    * [`control_template`](01_modsel_workflow/01_mcmc3r/control_template/): [the template control file](01_modsel_workflow/01_mcmc3r/control_template/mcmctree_tmp.ctl) with the same settings that were used by [dos Reis et al. (2015)](https://doi.org/10.1016/j.cub.2015.09.066) when analysing the 54-animal tree can be found in this directory. This template file is used by [our in-house `R` script](01_modsel_workflow/01_mcmc3r/scripts/Generate_BFs_inp.R), which appends the beta value to each control file that `MCMCtree` will use when sampling from the corresponding power posteriors.
    * [`MCMCtree`](01_modsel_workflow/01_mcmc3r/MCMCtree/): directory generated by [our in-house `R` script](01_modsel_workflow/01_mcmc3r/scripts/Generate_BFs_inp.R) with all the updated control files (i.e., same settings as in our [template control file](01_modsel_workflow/01_mcmc3r/control_template/mcmctree_tmp.ctl) but with a new line including the corresponding beta value that will be used during the MCMC when sampling from the corresponding power posterior). There are as many directories as power posteriors required to approximate the marginal likelihood for this dataset (i.e., 128). Please read the corresponding [README.md file](01_modsel_workflow/README.md#2-run-mcmc3r-to-select--values) to learn more about how you can run our in-house `R` script to generate the file structure that `MCMCtree` will later use.
    * [`scripts`](01_modsel_workflow/01_mcmc3r/scripts): [our in-house `R` script](01_modsel_workflow/01_mcmc3r/scripts/Generate_BFs_inp.R) to run `mcmc3r` and generate the files structure that `MCMCtree` so that it samples from the power posteriors can be found here. Please read the corresponding [README.md](01_modsel_workflow/README.md#2-run-mcmc3r-to-select--values) file to learn how to execute this script and reproduce our results.
  * [`02_MCMCtree`](01_modsel_workflow/02_MCMCtree/): this directory contains the [in-house bash script inside directory `scripts`](01_modsel_workflow/02_MCMCtree/scripts) to create the pipelines that will be used to run `MCMCtree`, which are saved in [directory `pipelines_MCMCtree`](01_modsel_workflow/02_MCMCtree/pipelines_MCMCtree). Details about how to execute the bash scripts on a server can be found in the [main `README.md` file inside the `01_modsel_workflow` directory](01_modsel_workflow/README.md).
  * [`03_mcmc3r`](01_modsel_workflow/03_mcmc3r/): once the analyses with `MCMCtree` have finished, we can analyse the samples collected during the MCMC when sampling from each power posterior and estimate the marginal likelihood (as well as the corresponding S.E. and the posterior probabilities for each hypothesis tested) with the `mcmc3r` `R` package.
    * [`HPC`](01_modsel_workflow/03_mcmc3r/HPC/): this directory contains all the input and output files required/generated by `MCMCtree` (more details in [section `3. Run MCMCtree` in the `README.md` file available within the `01_modsel_workflow` directory](01_modsel_workflow/README.md#3-run-mcmctree)). Please note that the 128 $\beta$ points used to sample from the corresponding 128 power posteriors are previously calculated by the `mcmc3r` `R` functions included in [our in-house `R` script](01_modsel_workflow/00_mcmc3r/scripts/Generate_BFs_inp.R), which are then saved in the `betaweights.txt` file. The `mcmc.txt` file output by `MCMCtree` (i.e., the sampled likelihood terms are saved in this file, which is output for each diversification model and for each power posterior) is read by various `mcmc3r` `R` functions, alongside the previously generated `betaweights.txt` file, to estimate the marginal likelihood value of each diversification model (more details in the [section `4. Run mcmc3r to estimate marginal likelihoods values` available within the `01_modsel_workflow` directory](01_modsel_workflow/README.md#4-run-mcmc3r-to-estimate-marginal-likelihoods-values)).
    * [`scripts`](01_modsel_workflow/02_mcmc3r/scripts/): this directory contains [our in-house `R` script](01_modsel_workflow/02_mcmc3r/scripts/Calculate_mlnL_BFs.R) to estimate the marginal likelihood, compute BFs, and posterior probabilities that we will use to select the best-fitting model to the 54-taxa animal dataset. Please read [the corresponding section in the `README.md` file](01_modsel_workflow/README.md#4-run-mcmc3r-to-estimate-marginal-likelihoods-values) to learn how to execute this script and reproduce our results.
* [`02_rate_per_branch`](02_rate_per_branch/README.md): in this directory, you will see one directory for each step that needs to be followed when running `MCMCtree` under the approximate likelihood calculation while printing the branch rates (i.e., `print = 2`).
  * [`00_MCMCtree`](02_rate_per_branch/00_MCMCtree/)
    * [`HPC`](02_rate_per_branch/00_MCMCtree/HPC): within this directory, you will find the file structure with the input files we will upload on a server to run `MCMCtree`. The first section in the [`README.md` file](02_rate_per_branch/README.md#1-run-mcmctree) includes various code snippets that you can use to prepare the contents within this directory while including tips to transfer this to a server.
    * [`scripts`](02_rate_per_branch/00_MCMCtree/scripts/): this directory includes two scripts that are used to obtain the bash scripts that will be submitted to a server to run `MCMCtree` (i.e., job arrays). If you have a different schedulers to SGE, then you will need to adapt these scripts if you want to follow the step-by-step guidelines detailed in the [`README.md` file](02_rate_per_branch/README.md#1-run-mcmctree).
    * `sum_analyses`: this is a directory that cannot be committed to GitHub due to its large size. If you follow the guidelines from the second section in the [`README.md` file](02_rate_per_branch/README.md#2-analyses-with-mcmctree-when-sampling-from-the-prior) onwards, you shall be able to reproduce its contents. You can download the original `sum_analyses` directory from our [FigShare repository](https://doi.org/10.6084/m9.figshare.32033958) and save it in this directory if you want to continue with the subsequent MCMC diagnostics.
  * [`01_MCMC_diagnostics`](02_rate_per_branch/01_MCMC_diagnostics/)
    * [`calibs`](02_rate_per_branch/01_MCMC_diagnostics/calibs/): this directory includes the [`R` script](02_rate_per_branch/01_MCMC_diagnostics/calibs/scripts/Include_calibrations_MCMCtree.R) alongside the [input `csv` files](02_rate_per_branch/01_MCMC_diagnostics/calibs/raw) required to generate the calibrated tree files in `MCMCtree` format. The [`raw` directory](02_rate_per_branch/01_MCMC_diagnostics/calibs/raw) includes both the input `csv` files and output files generated by the [`R` script `Include_calibrations_MCMCtree.R`](02_rate_per_branch/01_MCMC_diagnostics/calibs/scripts/Include_calibrations_MCMCtree.R). The [`inp_calibs` directory](02_rate_per_branch/01_MCMC_diagnostics/inp_calibs) contains files output by a subsequent in-house `R` script that will be run during MCMC diagnostics.
    * [`dummy_aln`](02_rate_per_branch/01_MCMC_diagnostics/dummy_aln/): dummy alignment with the same taxa names as those in the input tree files but only two nucleotides. This alignment is read much quicker by `MCMCtree` than a full alignment and, given that sequence data are not required for MCMC diagnostics, we will save time when `MCMCtree` reads both input files to check that the taxa names are the same (i.e., this file is used when `MCMCtree` is run when `print = -1`).
    * [`dummy_ctl_files`](02_rate_per_branch/01_MCMC_diagnostics/dummy_ctl_files/): template control file that is used at the end of the MCMC diagnostics to generate the evolutionary timeline that summarises the estimated evolutionary timelines across all the chains that passed the filters (i.e., this file is used when `MCMCtree` is run when `print = -1` as detailed in the relevant sections in the [`README.md` file](02_rate_per_branch/README.md)).
    * [`out_RData`](02_rate_per_branch/01_MCMC_diagnostics/out_RData/): some relevant output files generated by our in-house `R` scripts are saved here (saving the largest files with extension `RData` is optional, users can decide whether they want to output them or not).
    * `plots`: all the plots generated by our in-house `R` scripts are saved in this directory. The plots the R scripts save in this directory have been saved under their corresponding subdirectories in `sum_files_post` and `sum_files_prior`. You can download the `plots` directory we generated from our [FigShare repository](https://doi.org/10.6084/m9.figshare.32033958).
    * [`scripts`](02_rate_per_branch/01_MCMC_diagnostics/scripts/): all the `R` scripts that are used to carry out MCMC diagnostics are saved in this directory. The order in which they need to be used is detailed in the [`README.md` file](02_rate_per_branch/README.md), and the comments within each script clarify what tasks are completed by our in-house functions, which input files are required, and which output files shall be generated.
    * [`sum_files_post`](02_rate_per_branch/01_MCMC_diagnostics/sum_files_post/): at the end of the MCMC diagnostics, there are a set of code snippets that extract the most relevant output files generated by our in-house `R` scripts when summarising the data when sampling takes place from the posterior. These output files are classified in different subdirectories depending on what they are informative about.
    * [`sum_files_prior`](02_rate_per_branch/01_MCMC_diagnostics/sum_files_prior/): at the end of the MCMC diagnostics, there are a set of code snippets that we have included in the [`README.md` file](02_rate_per_branch/README.md) that we use to extract the most relevant output files generated by our in-house `R` scripts when summarising the data when sampling takes place from the prior. These output files are classified in different subdirectories depending on what they are informative about.
  * [`02_Summary_Rates`](02_rate_per_branch/02_Summary_Rates)
    * [`00_prior`](02_rate_per_branch/02_Summary_Rates/00_prior/): we use bash scripting as detailed in various code snippets in the [`README.md` file](02_rate_per_branch/README.md) to extract the "rategrams" (i.e., lines with the tree topologies and the branch rates as labels printed on the `out.txt` files generated by `MCMCtree` when `print = 2`) for each chain and partition (this procedure is carried out for each model and under both clocks).
    * [`01_posterior`](02_rate_per_branch/02_Summary_Rates/01_posterior/): we use bash scripting as detailed in various code snippets in the [`README.md` file](02_rate_per_branch/README.md) to extract the "rategrams" (i.e., lines with the tree topologies and the branch rates as labels printed on the `out.txt` files generated by `MCMCtree` when `print = 2`) for each chain and partition (this procedure is carried out for each model and under both clocks).
    * [`plots`](02_rate_per_branch/02_Summary_Rates/plots/): for each model and relaxed-clock model, we used [our in-house `R` script](02_rate_per_branch/02_Summary_Rates/scripts/Summarise_brates_mammals.R) to plot the evolutionary timelines with colour-coded branch lengths (i.e., ranging from faster- to slower-evolving rates) for each partition and then showing the average evolutionary rate per branch per model under each relaxed-clock model.
    * [`scripts`](02_rate_per_branch/02_Summary_Rates/scripts/): in this directory you can find [our in-house `R` script `Summarise_brates_mammals.R`](02_rate_per_branch/02_Summary_Rates/scripts/Summarise_brates_mammals.R), which we use to generate the abovementioned plots.
  * [`figs_tables`](02_rate_per_branch/figs_tables/): summary tables and figures that are output in a relevant format almost-ready to be used to include in a manuscript.
    * `out_RData`: object that summarises the evolutionary timelines estimated under each diversification model and relaxed-clock model (users can decide whether this object is to be saved when running our in-house `R` script).
    * [`plots`](02_rate_per_branch/figs_tables/plots/): all plots comparing the estimated divergence times for calibrated and uncalibrated nodes generated by out in-house `R` scripts are saved here.
    * [`scripts`](02_rate_per_branch/figs_tables/scripts/): the in-house `R` scripts that generate all [`plots`](02_rate_per_branch/figs_tables/plots/) and [`tables`](02_rate_per_branch/figs_tables/tables/) are saved here.
    * [`tables`](02_rate_per_branch/figs_tables/tables/): all tables comparing the estimated divergence times for calibrated and uncalibrated nodes generated, as well as the MCMC diagnostics under each model, are saved here.
